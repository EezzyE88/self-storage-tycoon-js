## Implemented presentation

- Cream walls, orange ribbed drive-up doors, teal trim, greener lawn and warmer daylight, using V62's existing shared materials and textures.
- Hollow open-topped units replace solid body boxes. Camera-facing walls cut to low sills; far walls retain depth. Existing door directions, animated curtains, unit numbers and status marks remain.
- Batched interior cartons/sofa decoration follows existing lease presence; a toolbox follows existing repair/make-ready jobs. Contents are representative decoration, not tenant inventory or a new game system.
- Open office interior with counter, screen and chair, retaining its V62 entrance and frontage treatment.
- Existing V62 person walk/work poses, carts, vehicle wheels, gate and door animation remain. No fake agents, alternate routes or new simulation activity.
- V62 exterior shell and floor selection behavior remain, so upper-floor interiors are accessed through the accepted floor controls. No new cutaway or camera control is introduced.
- New geometry is shared and instanced by floor and material. On the seeded Maple CPU fixture, static mesh nodes decrease from 308 to 267; shadow-casting mesh nodes from 160 to 111. These counts do not establish draw calls, FPS, mobile performance or visual quality.

Runtime changes: `js/render.js`, new `js/openhouse.js`, and `js/version.js`. Simulation, economics, progression, data, input/main loop, UI/CSS, audio, save and storage code retain exact baseline Git blobs. The presentation reads simulation state but never dispatches commands or changes state. No normal save was opened. No browser storage was accessed.

## Validation actually executed

Ten existing focused scripts pass: tbuildability, tbuildability_save, tcontrol_access, tdisplay_repair, tfinancial_trust, tgestures, tmenu_touch, tpause_policy, tsave_recovery and tthreefloor_save. Results/logs are in `docs/releases/v62-open-house-20261022/`.

New `tests/headless/topenhouse.mjs` passes real Three.js scene construction with Canvas/GPU stubs: camera cutaways in four orientations; four entrance directions; 1x1 fixtures; floor-scoped visibility on floors 0/1/2; contents within footprints; occupancy-dependent decoration; day/night and animation without state mutation; stable rebuild counts. Protected renderer methods (placement preview, bounds, camera pan/zoom, floor application, dynamic agents and poses, door finish) compare identical with V62 when the optional baseline renderer file is supplied.

Syntax checks pass for both changed renderer modules. Baseline runtime hashes and source lineage are recorded in `provenance.json`. Existing tests and new visual tests use disposable seeded state.

Harness issues: original CPU renderer loader could not resolve the new browser module from a data URL; the loader now resolves its imports without replacing its implementation. An initially omitted test prerequisite was fetched unchanged. A synthetic upper-floor fixture initially omitted V62's required floor arrays; it was corrected using `ensureFloors`. These were harness/setup failures, not confirmed game defects. A local Playwright launch failed because its Chromium executable is not installed; no renderer recovery or installation was attempted.
